DLM Core Contributions (vs. Standard NLP RAG)
🧬 Neural Cross-Encoder Reranking — BGE-Reranker-Large
Unlike bi-encoders that embed query and document separately, cross-encoders concatenate them and run a full transformer over the combined input — capturing fine-grained token-level query-document interactions. This produces dramatically more accurate relevance scores at the cost of O(n) inference.
Input: [CLS] query_tokens [SEP] document_tokens [SEP] Model: 24-layer DeBERTa transformer (560M params) Output: sigmoid(W · h_[CLS]) ∈ [0, 1] Key: Cross-attention over Q+D jointly → scalar relevance score
⚗️ Reciprocal Rank Fusion — Hybrid Dense+Sparse Search
BGE dense embeddings capture semantic similarity while BM25 captures exact keyword matches. Neither alone is optimal. RRF fuses both ranked lists without requiring score normalization — stable across heterogeneous retrieval systems.
RRF_score(d) = Σᵢ 1 / (k + rankᵢ(d)) where k=60 (smoothing), i ∈ {BGE Dense, BM25 Sparse} Result: Higher rank in either list → higher fused score
🔒 Session-Only Document Storage
All uploaded documents are embedded and stored in memory for the current browser session only. No data is ever written to ChromaDB or disk. When you close the tab, documents are automatically cleared. This design ensures privacy and allows multiple users to upload different documents simultaneously without interference.
Upload → Parse → Chunk → Embed → RAM (session_id keyed) Query → Cosine similarity search on session vectors Unload → DELETE /api/session → memory freed
🌐 Multilingual RAG Pipeline
Questions can be asked in any language. The system translates the query to English for optimal retrieval (since embedding models are trained on English), retrieves relevant context, generates the answer, then translates back to the user's preferred language — all automatically.
User Query (any lang) → Translate to English → Retrieve → Generate answer (English) → Translate to target lang → Show answer in user's language
🤖 ReAct Agentic Loop — Reason + Act Framework
Agentic RAG enables multi-hop reasoning: the LLM decides when to retrieve, when to calculate, and when it has enough information. The Reflexion extension adds verbal self-evaluation, letting the agent learn from failed attempts within a session.
Loop: Thought → Action(tool) → Observation → Thought → ... Tools: [retrieve | calculate | fact_check | summarize | final_answer] Reflexion: evaluate(attempt) → reflect(mistakes) → retry with context
Technology Stack
🔷
BGE-Large-EN-v1.5
1024-dim bi-encoder. Best open-source dense embedder for retrieval tasks.
🏅
BGE-Reranker-Large
560M cross-encoder. Fine-tuned on MS-MARCO for passage reranking.
🦙
Llama-3-8B-Instruct
Meta's 8B model with 4-bit QLoRA. Runs on 6GB VRAM via bitsandbytes NF4.
💾
In-Memory Session Store
Per-session RAM store. Documents never touch disk. Cleared on page close.
🔶
BM25 (Okapi)
Classic sparse retrieval. Complements dense search for exact keyword matching.
📊
RAGAS Framework
LLM-based evaluation: faithfulness, relevancy, precision, recall — no ground truth needed.
🌐
15+ Languages
Ask in Hindi, Arabic, Spanish, Chinese and more. Answers returned in your language.
⚡
FastAPI + SSE
Async REST API with Server-Sent Events for real-time streaming generation.
